# Agent Guidelines for WinTools

## Overview
WinTools is a PowerShell-based collection of one-shot Windows utility scripts that download, execute, and clean up portable tools.

## Directory Structure
- `/public/scripts/` - Individual tool scripts (one per utility)
- `/public/commons/` - Shared helper scripts (downloadrun.ps1, urlsearch.ps1)
- `/public/get.ps1` - Interactive menu script that fetches and displays the tool catalog
- `/public/tools.json` - Central catalog of all tools with metadata (name, description, features, category, URL)
- `/src/` - Vue application and styles
- `/index.html` - Vite entry point for the grid catalog
- `/.github/workflows/pages.yml` - GitHub Pages build and deployment

## Build/Test Commands
- Vue/Vite: npm ci, npm run dev, npm test, npm run build, npm run preview
- Test individual script: `pwsh -ExecutionPolicy Bypass -File public/scripts/<scriptname>.ps1`
- Test remote execution: `irm https://wintools.poziel.dev/<scriptname> | iex`
- Launch interactive menu: `irm https://wintools.poziel.dev/get | iex`

## Domain Configuration
- Production domain: `https://wintools.poziel.dev/<scriptname>` (without `.ps1` extension)
- GitHub Pages serves real extensionless script files generated by the Vite endpoint plugin
- Helper fetch URLs: `https://wintools.poziel.dev/commons/downloadrun.ps1.txt` and `https://wintools.poziel.dev/commons/urlsearch.ps1.txt` (generated text copies for PowerShell response decoding)
- Interactive menu: `https://wintools.poziel.dev/get`
- Tool catalog (JSON): `https://wintools.poziel.dev/tools.json`
- Web interface: `https://wintools.poziel.dev` (index.html)

## Tool Catalog Management

All tool information is centrally managed in `public/tools.json`. When adding a new tool:

1. Create the script in `/public/scripts/` following the standard template
2. Add the tool entry to `public/tools.json` with:
   - `name`: Script filename without .ps1 extension
   - `displayName`: User-friendly tool name
   - `vendor`: Tool creator/vendor (optional)
   - `category`: One of the predefined categories
   - `description`: Comprehensive tool description
   - `features`: Array of key features (3-5 bullet points)
   - `url`: Full `https://wintools.poziel.dev/<name>.txt` URL; the website displays the equivalent extensionless alias

The catalog is used by:
- `public/get.ps1` - Interactive PowerShell menu
- `index.html` - Web interface
- Both stay automatically in sync with tools.json

## Code Style

**File Structure**: Each app script follows a standard template:
- Multi-line comment block describing the tool, its features, usage examples, and workflow
- Remote execution instructions as comments using `https://wintools.poziel.dev/<scriptname>` format
- Shortcut creation command as a single-line comment using the same domain
- Parameter hashtable (`$params`) with tool-specific configuration
- Final line: Remote invocation of `downloadrun` script via `https://wintools.poziel.dev/commons/downloadrun.ps1.txt`

**Naming**: Use lowercase filenames (e.g., `cpuz.ps1`, `cleanmgr.ps1`). Organize vendor-specific tools in subdirectories (e.g., `apps/microsoft/`).

**Parameters**: Define parameters as hashtables using splatting pattern. Common parameters: `Url`, `GithubMatch`, `ArchiveApp`, `AppArgs`, `AppAdmin`, `NoCleanup`.

**Error Handling**: Use try-catch blocks in core scripts. Validate required parameters and provide clear error messages.

**Comments**: Include comprehensive header comments explaining tool purpose, features, usage, and workflow. No inline comments unless necessary for complex logic.

## Migration constraint
The website conversion preserved PowerShell behavior and comments. Subsequent runner repairs are authorized separately: maintain compatibility with Windows PowerShell 5.1 and PowerShell 7, and validate with tests/downloadrun.ps1 without launching real utilities. All new UI work belongs in Vue components.
